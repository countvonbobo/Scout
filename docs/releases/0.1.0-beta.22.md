# Scout 0.1.0-beta.22

Beta 22 makes the application pipeline reflect genuine progress, keeps untriaged jobs tied to live individual adverts, improves tailored-CV reliability, adds offset weekday scanning, and fixes two frustrating phone and triage interactions.

## Pipeline and job triage

- Pipeline is now a drag-and-drop board for Jobs, Shortlist, Watch, Active, Accepted and Closed. Dropping a card persists the appropriate tracker status while preserving an existing active application stage.
- Ignored or explicitly declined jobs no longer appear as closed outcomes. Closed is reserved for roles where an application was genuinely rejected or stopped.
- Pipeline flags have been removed, and Scan health now lives with the dated scan reports.
- Selecting **No** on the Jobs page now removes the card immediately instead of waiting for the tracker write and a full reload. A failed write restores the card, and successful dismissals retain the Undo action.

## Live advert verification

- Jobs cards show their stored source advert directly.
- Each scan rechecks untouched Jobs entries without changing roles already marked Yes or No.
- Definite closures, missing individual advert URLs and generic careers or board-index pages are archived. Network failures remain unverified rather than being treated as closed.
- Repeated job-identity calculations are cached so larger scans stay responsive while deduplicating and checking adverts.

## Tailored CVs

- Tailored-CV previews now recognise the render-state fields returned by the API, so a current rendered PDF is no longer reported as missing.

## Scan scheduling

- Settings includes an **Alternating weekdays (no weekends)** preset. The primary provider runs Monday, Wednesday and Friday; the verification provider runs Tuesday and Thursday.

## Phone settings

- Settings now uses one reliable touch-scroll area instead of competing page and dialog scrollbars.
- The empty settings footer no longer covers the bottom of the settings list.
- Settings cards, long controls, checkboxes and radio buttons now stay usable within a phone viewport.

## Upgrade and compatibility

- No workspace schema, provider sign-in or backup-format migration is required.
- Existing tracker decisions, application history, reports, CV artifacts and private workspace data remain in place.
- Release tags are immutable. A correction is published as a new version rather than moving an existing tag.
